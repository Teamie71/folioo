> 기준일: 2026-10-30

메인 백엔드가 사용자 인증·첨삭 데이터·상태·결과 저장을 담당하고, AI는 검색·분석·생성을 수행합니다.
사용자용 조회·수정·삭제·재시도는 백엔드를 이용합니다.

## AI 진입점

공통 경로는 `/api/v1/corrections/{correction_id}`이며, `X-API-Key`로 인증합니다.

| POST 경로 | 처리 | 결과 전달 |
|---|---|---|
| `/rag` | 기업·직무 검색 및 기업 분석 | 백엔드에 검색 자료·기업 분석 저장 |
| `/pdf-extraction` | multipart `file`의 PDF를 활동별로 구조화 | 백엔드 완료·실패 콜백 |
| `/generate` | 선택된 원문의 첨삭과 총평 생성 | 백엔드에 첨삭 결과 저장 |

세 API는 `202` 접수 후 백그라운드에서 처리합니다. 응답 body에 생성 결과를 반환하지 않습니다.
완료 여부는 백엔드의 상태·저장 결과로 확인합니다. Swagger의 `202`만으로 완료를 판단하지 마세요.

## 입력과 인증

- `OPENROUTER_API_KEY`: 실제 LLM 실행에 필요합니다.
- `TAVILY_API_KEY`: RAG 검색에 필요합니다.
- `AI_SERVICE_API_KEY`: 메인 백엔드 → AI 요청의 `X-API-Key`입니다.
- `MAIN_BACKEND_URL`·`MAIN_BACKEND_API_KEY`: AI → 백엔드 요청에 사용합니다. 같은 환경의 주소·키를 사용하세요.
- 일반 로그인 access token과 경험맵 Bearer 티켓은 첨삭 AI API의 인증 키가 아닙니다.
- 첨삭에는 회사명·직무명·채용 공고와 선택 원문 1~4개가 필요합니다. 기업 분석·강조 포인트도 입력에 반영합니다.
- PDF 업로드는 최대 10MB이며, 구조화된 활동은 최대 4개입니다.
- 개발·운영 환경의 첨삭 ID와 인증 키를 혼용하지 마세요.

## 백엔드와의 처리 순서

### PDF 추출

사용자 업로드 → 백엔드의 PDF 상태 `GENERATING` 준비 → AI에 파일 전달 → 추출·검증 →
`POST /internal/corrections/{id}/pdf-extraction-result` → 백엔드 저장·화면 조회 순서입니다.

로컬 AI에 파일을 직접 보내면 추출은 실행돼도 백엔드의 PDF 상태가 `NONE`인 경우 콜백 저장이 거절됩니다.
PDF 추출 상태는 첨삭의 기업 분석·생성 상태와 별도입니다.

### 기업 분석과 첨삭

AI는 백엔드의 `GET /corrections/{id}`로 입력을 읽고,
`GET /internal/portfolios/{id}`로 선택 원문을 가져옵니다.
RAG는 검색 자료·기업 분석을 저장하며, 첨삭은 원문별 첨삭과 총평을 생성합니다.

첨삭 생성 전에는 백엔드가 선택 원문에 대응하는 결과 저장 항목을 준비해야 합니다.
AI의 `/generate` 직접 호출은 백엔드의 준비 절차를 대신하지 않습니다.
상태 전이는 백엔드가 검증하므로, 완료(`DONE`)된 첨삭을 임의로 RAG 단계로 되돌리지 마세요.

## 검증 범위

자동 테스트는 외부 LLM·HTTP를 대역으로 검증합니다. 실제 연동은 별도로 확인합니다.

- AI 처리: 실제 PDF 추출, 기업 분석, 첨삭·총평과 결과 형식 확인
- 저장 연동: 백엔드 사전 준비 → AI 처리 → 콜백·결과 저장 → 상태·화면 재조회

로컬 JSON으로 결과를 확인해도 백엔드 저장까지 검증된 것은 아닙니다.
기능별 실행 결과와 미확인 항목은 해당 PR·이슈에 기록합니다.
